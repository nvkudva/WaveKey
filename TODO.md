Parakeet is one-shot (transcribes on stop), so on-device dictation has no partials at all today; only the Google engine streams (`GoogleVoiceSession.onPartialResults` -> `onGooglePartial` -> `updatePartial`), and even there the partial goes to the strip, not the field. `ModelKind.STREAMING_ASR` exists in ModelCatalog and is unused. Candidates measured Sept 2026: sherpa-onnx streaming Zipformer English `sherpa-onnx-streaming-zipformer-en-2023-06-26` int8 is ~70 MB total (encoder 68 MB + decoder 1.3 MB + joiner 254 KB) and drops straight into the existing sherpa-onnx runtime — this is the model the fork already removed for inaccurate live text (see ModelCatalog), so re-adding it means partials only, never the committed text; the 2023-06-21 and 2023-02-21 exports are ~180 MB int8. NVIDIA `nemotron-speech-streaming-en-0.6b` is stronger (600M params, cache-aware FastConformer, selectable 80 ms / 160 ms / 560 ms / 1.12 s chunk latency, NVIDIA Open Model License) but ships safetensors + GGUF with no ONNX export, so Android use needs an export path we do not have. Moonshine v2 Tiny (~27M params, ~50 ms latency) is the small-and-fast option. Cheapest first step is not a model at all: route the Google engine's existing partials into the text field instead of the strip. Weigh the RAM of holding two ASR engines against the <=60 MB typing-only budget (PLAN W6.2), and re-read PLAN R27 — two-model alignment was cancelled once already.
